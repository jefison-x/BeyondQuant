# ADR-0119：补数完成后自动复查并继续原研究

- Status: Accepted
- Accepted: 2026-11-24，维护者明确回复“接受 ADR-0119，继续实施”
- Date: 2026-11-24
- Scope: ADR-0118 支持的 A 股研究补数及原会话的自动接续。

## 背景

测试环境的助手已能提交限范围补数，数据中心能在后台完成并核验持久数据覆盖。会话的完成通知目前由下一次主动提问拉取。用户要求自动发现缺口、完成补数、复读数据，并在等待较长时自动继续原研究，期间无需用户刷新、点击或再次提问。

ADR-0111 已允许可信业务完成事实驱动自动接续，同时保留用户设置、身份和未知结果保护。当前 F6 接续只接受绑定 SignalJob 和结果 Artifact 的事件，只读业务工具限定为研究任务和回测读取。补数回执与行情、估值及财务读取需要单独的事件合同和接续权限。

## 决策

1. 助手通过 ADR-0118 的现有入口申请原问题需要的精确补数。Backend 绑定活跃会话、工作区、授权的原执行与原始用户消息，复用 Data Worker 和共享补数任务。数据已就绪时，当前助手直接调用对应的持久数据读取工具，核验日期、口径、来源和缺项后继续。
2. Data Worker 继续在后台跟踪任务。只有冻结范围通过持久数据覆盖复查，Backend 才能产生供原会话消费的数据就绪事件。事件绑定原用户消息、准备回执、已核验范围和具体数据版本。失败与尚未发布保留各自状态。执行时间不设隐含产品期限，等待期间不占用模型持续调用。
3. Gateway 复用现有注册会话接续消费者和 Runtime Adapter。对一个事件最多一次自动派发，使用原会话、原问题和当前用户有效的自动接续及执行选项。等待原执行准确结算后，再由 DSH 接续。新消息改变任务时、用户停止、会话归档、执行未结算或结果未知时，遵守现有取消和并发保护。重复通知及服务重启通过持久事件与准确回执对账。
4. 接续事件使用独立的只读权限，保留原模型资格与现有 SignalJob/Artifact 合同。允许助手对当前已核验的数据范围调用日线、估值和财务读工具，不授权新的补数、扩大范围、修改业务资产或发起交易。助手必须复读原研究用到的实际数据后才可下结论。复读发现缺项时，应明确其影响和未能核实的内容。
5. 状态与续研回答通过原会话显示，后台流程在浏览器关闭时仍继续。手动路径供主动补数或关闭自动接续的用户使用。数据覆盖检查、实际数据读取与研究回答分别留痕。

## 验收

- 用普通账号提出一个有真实缺口的 A 股问题。观察助手自动提交一次、真实数据入库、原会话自动发起续研、助手复读数据、原会话持久化研究回答，无需额外用户消息。
- 补数等待期间关闭浏览器，再打开同一会话，核对任务状态与回答。
- 覆盖立即可用、慢补数、实际复读仍缺字段、供应商失败、重复通知、取消、关闭自动接续及服务重启。不因重新登录或运行重启而重复提交原事件。
- 普通会话与旧 F6 路径仍受其原有权限、配置、模型资格和审计约束。
