# ADR-0071：1.0 主流机器学习支持与稳定性发布规划

- Status: Accepted
- Date: 2026-09-11
- Acceptance: 维护者要求“1.0版本应该在支持当前市面上常用智能机器学习模块开发运行稳定以后再发布。”，
  并在调研方案后确认“好的，就按这一份方案进行版本规划。”
- Scope: 产品版本里程碑、1.0 必备模块范围与发布验收；本次为文档规划维护。
- Supersedes: 历史 Phase 30/40/48 等 parity/体验完成被解释为足以进入或发布 1.0 的条件，
  以及仅收尾当前可靠性和数据闭环即可发布 1.0 的建议。历史验收事实不变。

## 决策

采用 [版本规划](../../roadmap/VERSION_PLAN.md)、[模块支持矩阵](../../roadmap/V1_ML_SUPPORT_MATRIX.md)
和 [发布验收](../../roadmap/V1_RELEASE_ACCEPTANCE.md) 作为 1.0 的生效规划基线。

1. 1.0 覆盖线性/树集成/提升树、基础和时序深度模型、小型 Transformer、模型组合及 HIST，
   同时具备特征、目标、验证、有限调参和可比较研究闭环。具体任务/profile 以矩阵为准。
2. 产品版本按 0.9.x 可靠性、0.10 数据基础、0.11 传统模型、0.12 提升树、0.13 深度基础、
   0.14 注意力/调参/融合、0.15 HIST、1.0 RC/正式发布推进；里程碑不是实施 Phase 授权。
3. HIST 历史关系及深度环境资格在 0.10 提前调查；缺口显式阻塞，不能静默省略必备项。
4. 1.0 以精确 model/task/profile 全流程、三次复现、故障恢复、资源边界及最终候选至少14天
   连续观察作为验收基础；盈利不作为软件稳定性的通过标准。
5. 产品版本、DSH 依赖、Phase、build ID 和镜像 digest 分开管理；不重写旧制品。
6. 正式1.0仍需维护者具名发布决定，并执行 ADR-0015 的 auto-merge 关闭。

## 授权与现有架构

本次接受的是交付目标和发布门槛，不是 GPU、HIST、调参、任意模型代码或新 Worker 的实施 ADR。
ADR-0043/0048 的运行边界和禁止项继续生效；各批实施前须明确新增合同、资源、制品格式及对应
Accepted ADR。无 Product/Engineering 扩权，不改变 DSH、MCP、数据库或前端边界。

Phase 97/Beta 不变。STATUS 下一 Product Phase 仍未授权；新版本规划不关闭 F2/S3、全接口审计或 U8。
本次不更改 package version、不创建 tag/Release、不自动部署、不启动数据扩容或新模型开发。
已有维护按原授权推进，版本清单不授权生产历史研究续跑或数据恢复。

## 后果

已有 LightGBM/Ridge、walk-forward 和专家路由可复用适用证据，不能直接视为新矩阵全部通过。
模型数量以冻结清单为准，不追逐全部新算法；Chronos/TimesFM 等可后续评估。
范围变更必须明确修订本 ADR 和矩阵，保留理由。80–140 工程人日是待资格调查后重估的粗估，非交付日期。
