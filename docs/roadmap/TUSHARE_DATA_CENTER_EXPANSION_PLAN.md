# BYQ 数据中心与 Tushare 扩容开发计划

首批已实现会话和回测共用的指数历史补数，并通过隔离环境的真实数据覆盖核验。完整产品流程待测试环境验收。基线核查日期为 2026-11-25。长期目标是 BYQ 数据中心 MCP 的数据能力覆盖达到或超过 Tushare 官方 MCP。

## 技术路线

- **统一入口。** 会话助手经 BYQ MCP 检查覆盖、提交需求、查看回执和读取已核验数据。回测后台使用同一项数据中心领域能力检查并准备其已声明的数据。浏览器经 Product API 展示实际任务状态。 [BYQ MCP 边界](../../ARCHITECTURE.md#d-mcp-边界)
- **统一供应商路径。** Data Worker 使用现有 Tushare API 适配器获取数据。供应商接入范围限于现有 API 契约，助手侧使用 BYQ MCP。
- **统一数据结果。** Backend 负责数据类型、任务权限、覆盖规则及归属。数据中心保存来源、时间范围、原始单位、核验结果和数据版本，研究答复与回测快照都引用实际使用的版本。 [供应商契约](../contracts/data-provider.md)

## MCP 能力对标与验收口径

对标单位为用户能实际发现并调用的数据能力。清单为每项能力记录官方 MCP 的已知操作、对应 Tushare API、BYQ 的调用入口、市场和标的、字段及单位、频率、历史区间、查询方式与授权要求。一个 BYQ 工具可以承载多个数据类型，每项在能力目录中仍可单独发现和调用。已支持的查询形态应覆盖对应官方能力，例如按标的和区间查历史、按日期查截面、按字段筛选和对长结果分页。

从官方公开资料和接口文档建立对照。官网的 300 多个标准化数据 API 属于 API 目录。未找齐的官方 MCP 工具清单在对标记录中标记为待核实。实现和运行沿用 BYQ MCP 与现有 Tushare API。 [Tushare 数据通道](https://tushare.pro/home/) · [官方 MCP 指南](https://tushare.pro/document/1?doc_id=463) · [Tushare 权限目录](https://tushare.pro/document/1?doc_id=108)

每项分别记录公开支持、账号实际可用、BYQ 已接入与产品已验收。当前套餐可用的项目进入交付队列，额外权限与待核实的项目仍保留在总对照清单中。每批以真实授权、实际数据覆盖和会话或回测执行结果更新状态。只有官方对应能力、相同授权下的可用范围及 BYQ 实测结果逐项对上，才判定该批达到对标目标。

## 套餐和 BYQ 现状

- Tushare 官网个人标准年档为 500 元、5000 积分，常规接口档位为每分钟 500 次。具体接口有各自的频次、记录上限、发布窗口和覆盖范围。首期用测试环境现有授权凭据做小样本鉴权与覆盖复核，以实际结果登记可用能力。多用户使用和数据展示范围按所购授权核对。 [积分与频次](https://tushare.pro/document/1?doc_id=290) · [服务条款](https://tushare.pro/document/1?doc_id=405)
- 生产只读盘点显示，沪深 300 日线 35 条，覆盖 2026-09-28 至 2026-11-24，中证 500 为 0 条。上交所日历 60 条，覆盖 2026-09-27 至 2026-11-25。生产未发现指数每日指标表及基金、宏观专用数据表。
- 现行会话自动补数覆盖有界个股需求。回测已有基准指数同步，Data Worker 已能分段拉取指数日线、写入指数库。代码还有指数每日指标存储模块，以及基金目录、净值和 ETF 日线适配器。基金和指数指标历史阶段的完成记录可作为复用线索，当前交付以生产入口、覆盖和真实流程为准。 [会话授权](../architecture/adr/ADR-0118-conversation-research-data-repair.md) · [回测指数数据](../architecture/adr/ADR-0030-benchmark-point-in-time-declared-data.md) · [历史阶段记录](IMPLEMENTATION_PLAN.md)

## 开发与验收

### 1. 接通十年宽基日线

| 步骤 | 开发内容 | 完成标志 |

| P0.1 核对权限与范围 | 在测试环境用经授权的凭据，对两个指数近期和历史样本调用 `index_daily` 和 `trade_cal`。记录真实的标的覆盖、行数上限、频次和返回字段。提交 ADR，明确普通用户在自己活动会话中申请沪深 300、中证 500 最长 10 年指数日线及所需日历，续研只读同一已验证范围。 | 接口样本、历史覆盖边界和权限范围明确，维护者接受相应 ADR。 [现有会话授权](../architecture/adr/ADR-0118-conversation-research-data-repair.md) · [现有续研授权](../architecture/adr/ADR-0119-automatic-research-after-data-preparation.md) |

以 2016-11-25 至 2026-11-24 为固定十年对照区间，按以下顺序验收：

1. 普通用户在测试环境发一次原指数研究问题，产生一项需求。关闭页面后继续同步。上交所日历覆盖全区间，每只指数的已发布且适用开市日均有记录，代码、日期、行数和口径核对通过。
2. 重新打开原会话，确认助手已复读指数实际数据并自动回答，引用来源和截止日。对比冷补数和再次读取的各阶段耗时，分别记录后台同步、核验与续研耗时。
3. 在现有回测允许的范围内选择十年数据内的重叠窗口。准备好策略和其他回测输入，使用同一指数基准验收回测直接复用已入库数据。核对冻结的基准版本和覆盖范围。
4. 补测会话和回测并发请求同一缺口、供应商权限不足或限流、未发布日期、Worker 重启和用户停止续研。确认回执归属正确，任务可对账，终态与覆盖一致。

### 2. 接入宽基估值与基金研究

- 宽基估值使用字段级覆盖，分别核对 PE、PB 的样本数、估值口径、空值和数据起点。用中证 500 做首个历史分位验收。先复用现有 Backend 存储和校验，再补现有 Worker 与 MCP 入口。
- 基金先验目录与份额代码，选会话里的 `015915` 和一只场内 ETF 做两条真实研究验收。报告区分场外净值和场内成交价，明确净值日、公告日、分红和复权口径。持仓以披露范围、报告期及公告日标注，验收未来报告在历史截止日前不可见。基金回测资格根据对应产品规则单独验收。

### 3. 接入行业与宏观研究

- 行业先做申万一级的走势、估值与同期比较。固定分类版本和数据来源，验证跨版本可比性。把历史可见的成分和权重冻结到回测快照。
- 宏观先用真实可核对的统计期验证四项指标和原始来源。在宏观阶段判断的测试题中，区分当月同比、环比、当季同比及发布日期。缺少首次发布或历史修订记录的序列可用于注明版本的当前描述，待具备时点证据再进入历史回测。

### 4. 逐项补齐能力清单

P0 提交首版对照清单，并用两只宽基指数验证清单、权限和真实调用的验收方法。P1、P2 和后续批次增量更新各自品类的覆盖。新增能力共用数据中心的覆盖检查、按需同步和版本机制。每项报告已验收的字段和区间、缺失范围及后续处理。

每批保留三类证据，分别是实际账号权限、数据覆盖与口径、会话或回测的端到端结果。按现有流程先在测试环境验收，再以独立 PR 交付，生产发布单独确认。
