# 1.0 稳定性与发布验收

Status: Accepted planning baseline — 2026-09-11。
依据 [ADR-0071](../architecture/adr/ADR-0071-v1-machine-learning-release-plan.md)。
[模块矩阵](V1_ML_SUPPORT_MATRIX.md) 中的全部必备模型、任务和研究模块通过后，才能进入 1.0 正式发布门槛。

## 功能、数据与运行

| 门槛 | 必须提供的证据 |
|---|---|
| 现有整改 | 完整 F2、S3、全接口审计及其故障回归的最新结论；历史 U8 提前结束与失败证据保留 |
| 真实闭环 | 每个必备模型在已批准真实数据基准上完成训练→样本外预测→信号→原生回测→报告；界面与小巴入口验收 |
| 数据正确 | 同日股票不跨切分；预处理、模型选择和融合只用允许窗口；标签可见性、历史成分/关系、财务时点可证 |
| 制品可追溯 | 数据、特征、目标、预处理、参数、代码、环境、模型、预测、信号身份完整，拒绝损坏或不匹配对象 |
| 重复试验 | 每个必备 model/task/profile 至少三次固定输入运行；确定性路径严格比对，其他路径事先冻结数值容差和理由 |
| 故障恢复 | 覆盖断连、超时、取消、Worker 被杀、服务重启、迟到结果；按任务语义恢复/重试/终止，不重复业务提交或永久 active |
| 资源有界 | 每个 profile 公布实测规模、内存、线程、并发、墙钟和制品上限；覆盖边界负载及受控超限失败 |
| 用户边界 | owner/workspace 隔离、权限撤销、审批、桌面/手机真实 Product API、进度/错误/恢复可见性验收 |
| 发布运维 | 新安装、从实际受支持基线升级、备份可读与摘要、精确旧镜像/配置保留、轻量回退路径有适用证据 |

固定环境含硬件/驱动和数值精度；不承诺跨 GPU、软件版本或设备逐位一致。
模型二进制身份校验与重新训练数值复现分开报告。检查点是否支持续训须由 profile 明确；
没有续训能力可按原任务受控重试或终止，不把重启后从头训练伪称断点续训。

研究亏损或某模型不优于基线不自动代表平台失败；指标正确、公平比较和结果可复现才是软件验收。
禁止挑选盈利窗口、隐去失败折或把安全失败计为成功研究。

## RC 连续观察

1. 对精确候选的完整服务 digest 组合至少连续观察 14 天，保留有负载的任务与资源记录。
2. 开始前冻结每个 profile 的代表性规模、正常任务次数、故障注入次数、允许数值容差和资源阈值。
   三次复现是最低要求，不代替负载次数。缺这些参数时观察不能标记完成。
3. 每个必备模型和任务都必须有正常闭环与适用故障覆盖；纯空闲健康探针不足以通过观察。
4. 发布阻断项包括：数据泄漏、越权、错误成功、重复领域提交、制品损坏、无法收口、无界资源增长等。
   正式发布时不能存在未解决的阻断项；其他限制由维护者审阅并明确记录。
5. 核心修复产生新候选，重新执行受影响回归与连续观察；未受影响证据只在依赖和组合身份可证时复用，
   最终候选须具有适用的完整 14 天观察证据。不能沿用已失败候选时长拼成 PASS。
6. 这是 1.0 发布验收，不要求每个普通补丁都重新执行 14 天观察或整库恢复演练。

原 U8 的 4 小时25分钟观察不转换为新 RC 稳定性 PASS；当前部署健康、CI 或 F6 完成也不能替代本门槛。

## 正式发布清单

- [ ] 所有必备 model/task/profile 和研究模块均有 release-verified 证据。
- [ ] 新增边界的实施 ADR 已接受并落地；Product Phase 完成状态与真实验收一致。
- [ ] 真实数据覆盖、HIST 历史关系、运行环境和资源资格无未解释缺口。
- [ ] 全矩阵回归及最终候选连续观察通过，无未解决发布阻断问题。
- [ ] 支持范围、已知限制、安装、升级、备份和轻量回退说明可执行。
- [ ] 发布清单、SBOM/来源证明、精确镜像及必要审计证据长期保留，不依赖短期 Actions artifact。
- [ ] 维护者明确批准具名 1.0.0 发布；从已验证 RC 提升相同 digest，不重编译。
- [ ] 按 ADR-0015 禁用 GitHub auto-merge 并恢复单维护者 Human Merge Gate。

范围调整需维护者明确修订 ADR-0071/矩阵并保留原因；尤其 HIST 缺数据不能被静默删除或改标完成。
这里不授权实际数据库恢复、生产研究续跑、模型训练费用、GPU 采购或任意正式 tag/release。
