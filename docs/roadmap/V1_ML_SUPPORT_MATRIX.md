Status: Accepted planning baseline — 2026-09-11。
归属 [版本规划](VERSION_PLAN.md) 与 [ADR-0071](../architecture/adr/ADR-0071-v1-machine-learning-release-plan.md)。
本表是待交付要求，不能作为 runtime capability registry 的 qualified 声明。

上表各行均为 1.0 必备目标；组合行中的每个模型、各任务分别建立验收记录。
基础 CPU profile 必须可用；GPU 为可选环境，仅对通过验收的设备/驱动/模型组合宣称支持。
深度模型应公布 CPU 的实测可用规模；若目标规模必须 GPU，则先修订支持环境和安装说明，不能用微型测试冒称规模化支持。

三类任务分别定义 label、loss、metric 和预测到信号语义；模型库能接收该 objective 不等于 BYQ 已支持。
分类/排序的具体目标、指标、类别/相关度映射在 0.11 合同阶段冻结，0.12 不得自行推定。
不要求所有深度模型在 1.0 同时支持分类、排序、GPU。

## 研究模块

| ID | 必备能力 | 交付要求 |
|---|---|---|
| RS-01 | 数据与特征 | 版本化价量、收益、动量、波动、流动性；历史股票池和明确覆盖范围；经过时点资格的估值/财务/行业特征分批接入 |
| RS-02 | 数据处理 | 缺失、异常、标准化、类别编码和序列窗口；需拟合的处理器仅在对应训练折拟合并冻结 |
| RS-03 | 目标与验证 | 回归、分类、排序；同交易日面板分组；保留 purged walk-forward、标签可见性和最终独立测试集 |
| RS-04 | 统一评估 | 每日截面 IC/Rank IC、分组收益、换手、费用后回测、回撤及跨窗口表现；分类另有任务指标 |
| RS-05 | 有限调参 | 已登记参数空间、trial/时间/并发/费用上限、持久结果与取消；不开放任意 objective 代码或无限 AutoML |
| RS-06 | 实验与模型比较 | 固定数据/切分/费用口径、训练成本、失败折、选择规则、参数及制品 lineage；不掩盖失败或只展示最好窗口 |
| RS-07 | Product 与小巴 | 能力发现、配置、进度、取消、错误恢复、结果/比较；小巴只能使用 qualified profile，经 MCP 执行 |

RS-01 不承诺所有财务/行业字段或全历史覆盖。每个宣称支持的特征都须有来源、许可、可见日期、
单位、生命周期及缺口证据；HIST 所需历史关系属于 ML-12 的硬门槛，不能以 RS-01 的分批策略省略。
RS-03/04 明确区分训练指标、选择指标和最终测试指标；同日并列值和不可计算指标需有合同，不默认填零代表有效结果。

## 验收记录模板

每个模型/任务/profile 创建一份记录，至少包括：

- model_id / task / capability_version / 对应实施 ADR；
- framework/python/runtime lock、CPU 或 GPU 与驱动、精确 image digest；
- 数据/特征/目标/预处理/切分/模型/预测/信号身份与许可；
- 支持的 rows、symbols、sessions、features、sequence length、模型大小、线程、并发、内存和时限；
- CI、真实端到端、三次复现、故障矩阵、双用户、浏览器及持续观察证据；
- 当前状态、失败项、限制、负责修复的批次及发布版本。

规划状态使用 planned → implementing → qualified → release-verified；blocked 必须有原因。
这些是规划台账状态，不改变现有 runtime 注册表的 qualified/disabled/blocked 协议。
现有模块可复用适用证据，但不能将其直接标成新 1.0 验收全部通过。
