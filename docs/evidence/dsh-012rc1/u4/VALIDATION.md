## Native module diagnosis

An intermediate image used `/nonexistent` as the non-root account home. The
official executable could not populate its `~/.cache/pkg` extraction cache, so
`node-pty` surfaced a misleading missing `pty.node` error and sandbox startup
also reported an explicit cache permission failure. The official source build
includes native `.node` assets and validates `pty.node`; pristine 0.1.2rc1 SDK
initialization succeeded as both root and non-root after the dedicated writable
home was introduced. Disabling `subprocess` or the inherited security services
was rejected and is not part of the final candidate.

The first full BYQ request after that fix exposed a second, independent
compatibility requirement: the official plugin-package request extension
requires active local package manifests to contain both `name` and `version`.
Adding the pinned local plugin version and a fail-closed generator check made
the scripted request complete successfully.
