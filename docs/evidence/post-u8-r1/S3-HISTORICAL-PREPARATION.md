# S3 历史指数成分准备：隔离整改记录

状态：**IN_PROGRESS**。依据 ADR-0062 §5，仅涉及已有 `index_weight` 能力；
不开发 Tushare 数据目录扩容，不推进 Product Phase，不部署或导入生产数据。

## 源检查与真实数据门禁

只读复核 Community 的 `IndexConstituentWeight`、`IndexWeightSyncState`、
`_run_index_weight_sync` 和 repository 的月度替换、同步标记及截至日期选择。
分类保持 migration inventory 的 `REFERENCE_ONLY` / `PORT_TESTS`；
整月破坏性替换和“月已同步即完整”仍为 `DROP`，没有复制旧同步实现。

2026-09-08 核查时，旧 Community PostgreSQL 没有运行中的容器；旧物理目录不能作为
BYQ 数据源启动、挂载或复制。仅核对连接位置元数据，没有读取或披露连接密码。
已请求只读逻辑导出或可用只读连接，尚未收到。此结论不是“旧缓存不存在”。
未认证来源、单位、时点和完整性的真实历史数据，不自动下载替代，也不宣称历史覆盖。

## 已完成的本地切片

- 单时点准备范围的纯合同：既有六指数目录、明确合法日期、上海当前日期的未来拒绝、
  最多 62 个日历日的封闭查找范围；明确 `historical_series=false`。这是准备计划，
  不是完整性证明；尚未接入 data-demand API、持久请求或 Worker，不能声称历史准备可用。
- 复现 6 项入库边界失败：错误指数、跨月、无效日期及非规范月份原先能进入写事务。
  现于事务前拒绝；不依赖 Provider 曾经验证，避免后续逻辑导入/重放绕开边界。
- 真实临时 PostgreSQL 复现 2 项历史覆盖丢失：空响应或少一个日期原先会清掉已验证日期。
  现按指数/月加事务锁，并在任何删除前拒绝缩减已验证日期；不把短响应解释为历史撤销。
- 同日不同成分的静默覆盖及并发竞争各有一个真实数据库失败复现。现于同月事务锁内
  核对既有已验证内容摘要，冲突明确拒绝并保留旧值；并发冲突仅一个胜出。
  没有新增自动纠正历史数据的权限，也没有将 Provider 新返回值视为覆盖授权。
- 历史一次性池遗漏/空日期以及未来日期原先能进入存储；另复现上海已跨日但默认日期仍为
  UTC 前一天。4 项永久失败测试先红后绿；历史创建现复用明确日期校验，持续跟踪默认日
  改为上海日期。未把日期校验当成历史数据准备已经完成。
