# H4 凭据原提交恢复与未知记录保留

2026-09-13，候选 `.79`。

凭据创建原键读取与写入现在在同一事务的有界锁内。八个独立连接复现了用户凭据唯一键冲突、
系统 NULL owner 凭据生成多个对象的问题；修复后同一原键只产生一个对象和一条创建审计。
历史已存在的重复身份明确冲突，不任取其一，也不修改生产历史数据。

新增用户凭据只读回执，经 Product API 按当前用户、操作、原请求键及目标凭据核对，
仅返回原凭据 ID 和提交版本。替换密钥、撤销之后仍能找到原创建和更新版本；已撤销对象的新撤销请求
留下同版本无副作用审计。密钥及加密信封不进入该回执，也未向 MCP 新增凭据能力。

浏览器只保存白名单元数据和请求标识；密钥只在内存中用于本次提交，结束后清除。
提交应答丢失后刷新页面，可以只读找回原对象，不能用目录当前状态冒充原操作成功。
原未知请求的后续重试即使遭遇 401 或其他明确拒绝，也不能据此清除先前未知提交记录；
模拟账户、反馈、股票池入口同步修复了这一问题。

验证：

- Backend 凭据定向测试 11 项通过，包括独立连接并发、历史歧义、跨用户/错目标/错操作及撤销后原版本。
- 前端提交记录与 settings 定向测试 5 文件 14 项通过；前端生产构建通过。
- 真实浏览器经隔离 Gateway/Product API：模拟账户创建与下单、账户导入、已提交后重试 401 三项通过。
  401 用例在修复前复现原记录被清除，修复后只读恢复原账户，无重复写入。
- 凭据真实浏览器一项通过：合成密钥创建在 Backend 提交后丢弃应答，刷新后 GET 找回原 ID/版本，
  创建 POST 只有一次，浏览器持久存储不含该密钥或密文。仅测试栈配置公开合成加密键，无 Provider 调用。
